# Rayfin storage & token cache injection (experimental)

## Where things are stored

### Workspace / deployment target (per-project, lives in the repo)

Under `hello-world/rayfin/`:

- **`.deployments.json`** — one entry per deployment name, plus which one is
  `"active"`. This is the source of truth for "which Fabric workspace/item am
  I pointed at".
  ```jsonc
  {
    "deployments": {
      "hello-world": {
        "fabricItemId": "cecc****-****-****-****-********02d6",
        "fabricWorkspaceId": "b6d5****-****-****-****-********6642",
        "fabricTenantId": "72f9****-****-****-****-********db47",
        "publishableKey": "pk-****-***-*********",
        "fabricDeepLink": "https://app.fabric.microsoft.com/groups/b6d5.../appbackends/cecc...?ctid=72f9...",
        "deployedAt": "2026-09-24T00:21:27.962Z"
      }
    },
    "active": "sql-telemetry-intelligence-engineering-dev-mdrrahman"
  }
  ```
- **`.env`** — the *active* deployment's values, flattened as `RAYFIN_PUBLIC_*`
  env vars, auto-managed by `rayfin dev`/`rayfin up`.
  ```env
  RAYFIN_PUBLIC_WORKSPACE_ID=b6d5****-****-****-****-********6642
  RAYFIN_PUBLIC_ITEM_ID=cecc****-****-****-****-********02d6
  RAYFIN_PUBLIC_TENANT_ID=72f9****-****-****-****-********db47
  RAYFIN_PUBLIC_PUBLISHABLE_KEY=pk-****-***-*********
  ```
- **`.project.json`** — a stable `projectOriginId` used only to correlate
  telemetry across scaffold/deploy events; not a deploy target.

Repo root **`.env.local`** mirrors `rayfin/.env` for the frontend framework
(Vite) and is regenerated by `rayfin env` — don't hand-edit it.

### Credentials (per-machine, lives in your home directory)

`~/.rayfin/` (override with `RAYFIN_CONFIG_DIR`):

- **`cache.bin`** — the MSAL token cache (access + refresh + ID tokens).
  Encrypted via OS keychain/DPAPI/libsecret by default; **plaintext** here
  because we're in a container and passed `--encryption-fallback-enabled`.
  ```jsonc
  {
    "Account": { "<home-account-id>": { "username": "you@microsoft.com", "...": "..." } },
    "AccessToken": { "<key>": { "client_id": "2f84****-****-****-****-********0fb6", "secret": "<REDACTED>", "expires_on": "..." } },
    "RefreshToken": { "<key>": { "client_id": "2f84****-****-****-****-********0fb6", "secret": "<REDACTED>" } }
  }
  ```
- **`auth.json`** — non-secret identity metadata (tenant ID, UPN, display name).
- **`dev-device-id`**, **`telemetry-notice-shown`** — misc local state, no secrets.

⚠️ `cache.bin` in plaintext mode contains a **live, usable refresh token**.
Never commit it, paste it into chat/logs, or copy it off this machine.

## Token cache injection

Templates for re-hydrating `~/.rayfin/cache.bin` from an existing `az login`
session, bypassing the interactive MSAL browser flow. This is unlikely to
fully work (see "Required scopes" below) and is documented for
experimentation only.

## Required scopes

rayfin-cli requests an access token for `client_id`
`2f844663-8e82-4a34-8b65-09d9d14b0fb6` with the following delegated Fabric
scopes (observed in `~/.rayfin/cache.bin`'s `AccessToken.target` field):

```
https://api.fabric.microsoft.com/Capacity.ReadWrite.All
https://api.fabric.microsoft.com/Catalog.Read.All
https://api.fabric.microsoft.com/Dataset.Read.All
https://api.fabric.microsoft.com/Item.Execute.All
https://api.fabric.microsoft.com/Item.Read.All
https://api.fabric.microsoft.com/Item.ReadWrite.All
https://api.fabric.microsoft.com/Workspace.ReadWrite.All
https://api.fabric.microsoft.com/.default
```

`az account get-access-token --resource https://api.fabric.microsoft.com`
instead mints a token for az-cli's own app
(`04b07795-8ddb-461a-bbee-02f9e1bf7b46`) with only `scp: user_impersonation`
— none of the granular scopes above — so Fabric endpoints that check for a
specific scope will reject it with `403`.

## Sample decoded JWT claims (fabricated example, not a real token)

What rayfin-cli's own access token looks like once decoded (illustrative
values only — every field below is fabricated):

```jsonc
{
  "aud": "https://api.fabric.microsoft.com",
  "iss": "https://sts.windows.net/{tenant-id}/",
  "appid": "2f844663-8e82-4a34-8b65-09d9d14b0fb6",   // rayfin-cli's app registration
  "scp": "Capacity.ReadWrite.All Catalog.Read.All Dataset.Read.All Item.Execute.All Item.Read.All Item.ReadWrite.All Workspace.ReadWrite.All",
  "oid": "00000000-0000-0000-0000-000000000000",      // object id, fabricated
  "sub": "AAAA0000BBBB1111CCCC2222DDDD3333EEEE4444",   // subject, fabricated
  "tid": "72f988bf-86f1-41af-91ab-2d7cd011db47",       // tenant id
  "upn": "you@microsoft.com",
  "exp": 1790213456,
  "iat": 1790209856,
  "nbf": 1790209856
}
```

What an `az account get-access-token` token for the same resource actually
decodes to (real shape, values redacted):

```jsonc
{
  "aud": "https://api.fabric.microsoft.com",
  "appid": "04b07795-8ddb-461a-bbee-02f9e1bf7b46",  // az-cli's own app, not rayfin-cli
  "scp": "user_impersonation",                       // missing all Fabric.* scopes above
  "tid": "72f988bf-86f1-41af-91ab-2d7cd011db47"
}
```

The `appid`/`scp` mismatch is why a naive cache injection using an
`az`-minted token will not satisfy rayfin-cli's Fabric API calls.
